# Internationalization

DeepSeekCode ships ten UI locales: `en`, `zh-Hans`, `zh-Hant`, `ja`, `ko`,
`es`, `fr`, `de`, `pt-BR`, `ru`. All user-visible text renders through the
`deepseekcode-i18n` crate; English is the source language and the fallback.

## Selecting a language

Precedence, highest first:

1. an explicit pin — desktop Settings → Language, CLI `--lang`, or the
   `ui.language` project config (`"auto"` or a BCP-47 tag such as `"zh-Hant"`);
2. `DEEPSEEKCODE_LANG`;
3. the POSIX chain (`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`);
4. the Windows UI language (`GetUserDefaultUILanguage`);
5. English.

An unknown tag degrades to `auto` instead of failing the load, so a config
written for a future release still starts.

The HTTP API additionally honours `Accept-Language` (with quality values) and
an explicit `X-DeepSeekCode-Locale` header per request. Every error body keeps
a stable machine-readable `code` plus three human fields:

```json
{ "error": "<localized>", "error_en": "<english>", "code": "not_found", "lang": "zh-Hans" }
```

Service failures add a raw-English `detail` so diagnostics are never lost in
translation (storage internals never leave the host).

## Rules for contributors

1. **Every user-visible string lives in all ten catalogs**
   (`crates/deepseekcode-i18n/src/locales/*.json`). English defines the key
   set; `cargo test -p deepseekcode-i18n` fails the build on a missing key, a
   dropped placeholder, an unparsable message, or a locale that is an
   untranslated copy of English.
2. **Placeholders must survive translation.** Reorder them freely, but never
   drop or rename them — the parity test compares placeholder sets against
   English.
3. **Never concatenate translated fragments.** Use `{placeholder}` or a
   `plural` arm so word order stays under the translator's control. Never
   parse numbers or structure out of *translated* text (the old
   `" for "` duration scrape is the canonical anti-example).
4. **Format values through the runtime helpers** (`count`, `percent`,
   `bytes`, `duration`, `date`, `time`), never through `format!`. German and
   Russian group digits differently; unit abbreviations are not English; date
   fields are never grouped (`2026`, never `2,026`).
5. **System prompts, tool descriptions, logs, telemetry, schemas and
   compaction summaries stay English.** They are read by models and
   developers, not end users, and a localized prompt would fork the provider
   prefix cache on every language change. The one exception is the fixed
   `LANGUAGE MIRRORING` block in the system prompt, which *instructs* the
   model to reply in the user's language while itself staying byte-stable.
6. **Wire labels stay English; display labels localize at render time.** The
   activity projector emits English `verb`/`label` for DB and API compat; the
   desktop maps `ActivityKind` to catalog keys when painting. Compare against
   canonical English tokens (`== "Ready"`), render through `status_text`.
7. The `common.*` keys are the shared vocabulary (OK/Cancel/Loading…/Retry).
   Prefer them over adding a new key.

## Adding a string

1. Add the English message to `en.json` (dotted namespace: `feature.name`).
2. Add the same key to the other nine files, translated, keeping every
   `{placeholder}`.
3. Use it via `deepseekcode_i18n::t("…")` or `tr!("…", "name" => value)`.
4. Run `cargo test -p deepseekcode-i18n` — it checks key parity, placeholder
   parity, message syntax, and per-locale rendering.

## Adding a locale

1. Add the variant to `Locale` (`locale.rs`) with tag, endonym, names, and a
   `Direction`.
2. Add CLDR plural rules (`plural.rs`) and number/date/duration tables
   (`format.rs`).
3. Add the catalog file and register it in `catalog.rs`.
4. Add `MUI_LANGUAGE` to `packaging/desktop/windows/installer.nsi`.
5. Detection (`BCP-47` parse, `Accept-Language`, OS locale) needs no change
   unless the locale has special matching rules.
